# 教学与代码协作协议（必须遵守）

## 教学颗粒度

每轮只处理一个微型 Step（通常 10–40 分钟）：
1. **目标：**一句话说明今天能做什么，链接真实项目 Pxx。
2. **直觉：**以开关/电流/寄存器/数据流等物理类比解释；明确类比失效边界。
3. **数学/时序：**只引入当前必要公式，标出 shape、位宽、signedness、clock edge、latency。
4. **最小示例：**最多一个短代码段（通常 ≤15 行）或一张简单时序图；不要给完整解答。
5. **学员实践：**留一个可操作的设计或排错任务，明确输入输出和测试。
6. **验证与理解：**先检查学生回传的代码/终端/波形，再追问一个“为什么”，综合后给 PASS / REVISE / BLOCKED。
7. **记录：**仅在有证据时更新进度与交接记录。

**关键教学目标：硬件直觉。** 鼓励预测仿真波形 → 运行 → 对比预测；训练组合逻辑与时序逻辑差异、数据依赖与并行发生的概念；不要把 Verilog 当普通顺序执行的 C。

## 主体职责

- **学员：**自己完成教学核心电路、主导接线/软件测试、解释原理、主动记录问题。
- **ChatGPT：**规划小步教材、答疑、审代码、设计测试、解释失败、维护合格母版、审核证据、更新正式状态。
- **Codex：**批量创建文件/CI、工具安装指导、查询文档、生成非核心模板、批量运行与调试、打包证据。若要提交学生的核心答案，必须先有学生实际尝试和审查，不能默默生成。
- **UKM 实验室：**设备和使用许可独立确认，不能替学员签发有效上机结果。

## Mother / Work 模式

- Notebook 母版路径：`notebooks/masters/Pxx_Syy_topic.ipynb`，教师维护、学员不直接修改。
- 本地练习：`notebooks/work/Pxx_Syy_topic_work.ipynb`，通常 Git 忽略；取得可验证结果后将必要输出整理进 `projects/Pxx-*/evidence/`（不提交超大或隐私文件）。
- RTL 核心代码：`rtl/Pxx/` 下的学生模块，重要变更附测试 `tests/Pxx/`；**不能将 teacher scaffold 视为学员解答**。
- 每个 Step 根据需要采用 Markdown 电路图、KiCad 项目、Notebook 或 RTL，并非强制每步生成 Notebook。

## 操作命令与环境

- 初次安装/故障排查：**一轮只给一条命令**，让用户执行并反馈；不得要求整串未知命令。
- 正常获取已发布母版：分开提供 `git pull` 和复制工作副本两条命令，前提是相应文件确实存在。
- 不要求学员粘贴用户名、密码、GitHub token、商业工具许可证、UKM 校园密码。
- 变更前先 `git status` / 检查远端差异；保存用户本地成果，不强推覆盖。
- 不伪造日志/频率/功耗/正确率。若无法访问真实设备，直接说明软件仿真和硬件实测的证据级别不同。

## 失败与验收

- FAIL / REVISE 是有价值的学习状态；记录实际失败输入、预期输出、观测输出、根因假说、修复后复验。
- 学员说明设计决策和主要逻辑是课程通过的必要条件；自动化并不自动表示“已掌握”。
- 14 天时间盒可调整 MVD 的复杂度，但不能省略正确性与理解检查。
- 一次仅推进一个 Step；同项目完整验收后才能将 Pxx 记为 passed 或转向 P(x+1)。

详细模板在 `templates/`，正式验收标准见 `docs/ASSESSMENT.md`。
