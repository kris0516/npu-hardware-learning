# 逐步验收与证据协议

## 状态含义

- `not_started`：题目尚未开展；包括仓库初始示例已经存在的情况。
- `in_progress`：学生开始尝试，有可核实的学习活动，但未满足全部验收。
- `needs_revision`：发现确切错误、遗漏的解释或测试，需修正后重验。
- `blocked`：硬件/环境/权限使必要项暂时无法进行；记录能完成的替代检查，但不可冒充实板完成。
- `passed`：**学生独立理解 + 正确实现 + 可复现证据** 全部齐备。

## 每个 Step 的验收项

1. **功能 / 正确性**：输入输出、正常案例、边界案例、reset/enable/overflow/有效性（若适用）与参考值一致。
2. **可复现**：源码、依赖/工具版本、从干净环境的命令、测试日志与文件链接。
3. **硬件直觉**：学生能解释至少一条关键数据路径、至少一个时序或位宽问题、至少一个设计权衡。
4. **原始证据**：波形、原理图/PCB ERC/DRC、sim log、板级照片与测试、Synthesis/STA/GDSII 报告（依项目），并标明仿真/估算/实测的证据类型。
5. **失败分析**：至少记录一个预测与观察差异、bug 或边界问题；若没有实际失败，也可讨论预设边界并说明为何覆盖。

## 项目通过条件（全部）

- Step 清单与最低演示 MVD 全部通过；没有尚未解决的关键功能错误。
- 在 `projects/Pxx-*/evidence/` 有实验/验收报告，包含 Git commit、日期、命令、证据、测试样本规模及实际结果。
- ChatGPT 审查本次提交与测试，并根据学员自己解释的内容明确写下“通过”；自动生成的样例不算学员作品。
- `learning/state.json` 对应项目才可更新为 `passed`，证据相对路径必须真实存在。
- P06 若无 FPGA 现场实测不能宣称板级 PASS；P08 GDSII 不等于流片，综合面积估计不等于晶体管/硅片实测功耗。

## 报告基本格式

见 `templates/LAB_REPORT.md` 与 `templates/STEP_RECORD.md`。最小记录字段：日期、Pxx-Syy、目标、学生贡献、工具/板卡/版本、设计参数（shape/bitwidth/clock）、预期、实测/仿真、命令、结果、解释、已知限制、教师审核结论。

## 分工及诚信

- Codex 可以创建测试、解释日志、帮助重复运行，但学生必须答出核心工作原理；若核心实现完全由 Codex 生成，必须明确标注“参考实现/辅助实现”，不可作为独立完成的学习成果。
- 任何假设性能数据须标注 `hypothetical`；禁止把估算、文献数据写成自己测量。
- CI 是代码回归网，**不是理解测验**。合格的项目报告可用于未来实习简历陈述。
