# NPU Hardware Learning

从数字逻辑出发，通过小项目逐步学习 MCU/PCB、FPGA/Verilog、NPU 架构和 ASIC 设计。每次只推进一个小知识点，完成验收后再进入下一步。

## 项目路线

| 项目 | 主题与成果 | 主要验收证据 | 状态 |
|---|---|---|---|
| P01 | 数字逻辑：门电路、组合逻辑与真值表 | 手算真值表、仿真和解释结果 | 未开始 |
| P02 | 时序逻辑：触发器、计数器与有限状态机 | 时序图、复位和边界测试 | 未开始 |
| P03 | MCU 与接口：GPIO、定时器及串行通信 | 可复现程序、连接图和实验记录 | 未开始 |
| P04 | PCB：原理图、布局布线与制造检查 | 设计文件、ERC/DRC 结果及检查记录 | 未开始 |
| P05 | FPGA/Verilog：可综合模块与板级验证 | 仿真、综合报告及可用时的板级证据 | 未开始 |
| P06 | 运算单元：定点数、MAC 与数据通路 | 软件参考模型、边界测试与资源报告 | 未开始 |
| P07 | 小型 NPU：数据流、存储、调度与矩阵运算 | 端到端结果与参考模型比较、性能记录 | 未开始 |
| P08 | ASIC 流程：综合、时序、物理设计和验证 | 可复现流程、报告及限制说明 | 未开始 |

路线可根据掌握情况和可用硬件调整。PCB 制造、FPGA 实板及 ASIC 流片不是默认前提；没有硬件时明确标注仿真验收的范围。

## 逐步验收规范

1. **定义一个小知识点**：写明目标、前置知识、输入输出和本次范围。
2. **学习与动手**：先解释原理，再完成一个足够小的练习；保留代码、图或笔记及运行方法。
3. **验证**：按照任务预先列出的正常、边界及错误情况进行检查；涉及 RTL 时运行自检仿真并核对参考结果。
4. **解释**：学习者说明关键概念、设计选择和结果；ChatGPT 检查理解与证据，给出明确的通过或待修正结论。
5. **记录并推进**：在进度表或项目记录中注明日期、证据链接、结果和问题。只有当前知识点通过后才开始下一个；不足之处先修正再复验。

ChatGPT 维护课程材料与项目母版、检查提交内容并更新进度；需要实物测量或用户操作时，记录真实结果，不虚构验收证据。自动化测试通过仅证明已覆盖的检查通过，不能替代理解与实物验收。

## 本地验证

需要 Python 3、Icarus Verilog（`iverilog` 和 `vvp`）。在仓库根目录运行：

```sh
python3 -m unittest discover -s tests -p 'test_*.py'
iverilog -g2012 -s tb_and_gate -o /tmp/npu-and-gate rtl/and_gate.v tests/tb_and_gate.v
vvp /tmp/npu-and-gate
```

示例门电路仅用于验证测试管线；课程从 P01 的第一个知识点正式开始。
